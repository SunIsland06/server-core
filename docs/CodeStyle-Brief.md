# C++ 项目开发与代码风格规范

本规范旨在保障工程代码风格高度统一、逻辑健壮，杜绝内存泄漏与并发陷阱，并适配现代 C++ 高性能服务端的开发标准。

---

## 一、 架构与文件组织 (Architecture & Files)

1. **文件扩展名**：头文件统一且强制使用 `.hpp`，源文件统一使用 `.cpp`。
2. **头文件保护宏**：头文件必须使用传统宏守卫，命名格式为 `#ifndef PROJECT_PATH_FILE_HPP`（全大写、下划线分隔）。
3. **声明与实现严格分离**：
* 类原型声明、方法签名全部写在 `.hpp` 中。
* 具体的函数体实现全部写在 `.cpp` 中。
* 严禁在 `.hpp` 中直接实现常规业务函数（模板类/函数和纯内联轻量函数除外）。


4. **命名空间语法**：使用 C++17 双冒号嵌套小写语法（例如 `namespace owner::project::network`）。
5. **头文件包含顺序**（自顶向下，组与组之间空一行）：
* 第一位：当前源文件对应的同名 `.hpp`（强制置顶，验证自包含性）；
* 第二位：本项目内部其他头文件；
* 第三位：第三方库头文件；
* 第四位：C++ 标准库（STL）头文件；
* 第五位：C 运行时与系统级头文件（如 `<unistd.h>`）。



---

## 二、 格式与排版约束 (Formatting & Syntax)

1. **缩进原则**：严格使用 **4 个空格** 缩进，**严禁使用 Tab 制表符**。
2. **层级缩进规则（逐层递进 4 格）**：
* `namespace` 顶格书写；
* `class` / `struct` 必须比所属的 `namespace` **多缩进 4 格**；
* 访问权限修饰符（`public:`、`protected:`、`private:`）比 `class` **再多缩进 4 格**；
* 成员变量与方法声明比访问修饰符 **再多缩进 4 格**。


3. **括号风格 (K&R 风格)**：
* 控制语句（`if`, `else`, `for`, `while`, `switch`）和函数的开括号 `{` 必须放在**当前行末尾**；
* 闭括号 `}` **单独成行**，并与对应的关键字在纵向对齐。


4. **强制复合语句块**：即使 `if`、`else`、`for`、`while` 的执行体**只有一行代码，也必须强制使用 `{}` 包裹**，严禁省略。
5. **空格与符号细节**：
* 二元运算符（`+`、`-`、`==`、`=` 等）两端必须各保留 1 个空格；
* 括号（`()`、`[]`、`{}`）内部两侧**严禁留白**；
* 指针 `*` 和引用 `&` 声明时**必须紧贴类型**，与变量名之间留 1 个空格（例：`int* ptr`，`const std::string& str`）。

## 三、 命名规范与变量访问 (Naming & Access)

1. **命名风格清单**：
* **类型 / 概念 / 文件名**：大驼峰（`PascalCase`），如 `TaskQueue.hpp`、`SessionContext`。
* **函数 / 局部变量 / 成员变量**：小驼峰（`camelCase`），如 `executeTask()`、`bufferSize`。
* **常量 / constexpr 变量**：全大写加下划线（`ALL_CAPS`），如 `MAX_BUFFER_SIZE`。
* **强类型枚举 (Enum Class)**：类型名与枚举项均使用大驼峰（`PascalCase`）。


2. **参数命名与 `_in` 作用域限制**：
* **仅构造函数的入参**强制添加 `_in` 尾缀（用于防重名与歧义，例：`Task(int id_in) : id(id_in) {}`）；
* **普通函数与成员方法入参严禁使用 `_in**`，保持常规小驼峰（例：`void run(int taskId)`）。


3. **成员变量访问铁律**：
* **构造函数初始化列表**：语法限制无法写 `this->`，必须**直接写变量名**（例：`: id(id_in)`）；
* **其余所有成员函数体内**：访问非静态成员变量**无例外强制显式书写 `this->**`（例：`this->size = 0;`）；
* 严禁使用 `m_` 或下划线前缀命名成员变量。


4. **静态变量**：类静态变量在访问时强制通过类名作用域限定（例：`TaskQueue::activeCount`）。

## 四、 类型设计与构造规范 (Type & Constructor Design)

1. **Struct 与 Class 的职责划分**：
* **`struct`**：仅用于纯粹的被动数据载体（POD / DTO），只包含公有数据；
* **`class`**：凡是包含私有状态、不变式校验或复杂业务行为的类型，必须使用 `class`。


2. **现代五法则 (Rule of Five)**：
* 析构函数、拷贝构造、拷贝赋值、移动构造、移动赋值这 5 个特殊成员函数，只要手动定义了**其中任意一个**，其余 4 个必须**显式声明为 `= default` 或 `= delete**`，严禁依赖编译器隐式生成。


3. **构造函数 explicit**：
* **除拷贝构造和移动构造外**，所有单参数构造函数必须显式标记为 `explicit`，杜绝隐式类型转换。


4. **成员初始化**：
* 成员变量必须在构造函数初始化列表中完成初始化，禁止在构造函数体内做赋值；
* 多个成员初始化时，每个成员必须各自**单独成行并缩进对齐**。


5. **虚函数修饰**：
* 具备多态特性的基类必须显式声明虚析构函数：`virtual ~Base() = default;`；
* 派生类覆写虚函数时**仅标记 `override**`（无需再写 `virtual`）。



---

## 五、 内存管理与性能 (Memory & Performance)

1. **堆内存管理**：**严禁手动调用 `new` / `delete**`，强制采用 RAII 模式，使用 `std::unique_ptr` 或 `std::shared_ptr` 管理动态资源。
2. **空指针**：统一且强制使用 `nullptr`，严禁使用 `NULL` 或整数 `0`。
3. **高效传参**：
* 只读字符串入参优先使用 `std::string_view`；
* 连续内存切片优先使用 `std::span`（C++20）或 `const std::vector<T>&`；
* 基础轻量类型（如 `int`, `double`, `bool`）**按值传递**；
* 重型对象传参优先使用 `const T&`；
* 需要接管所有权的对象使用右值引用 `T&&` 并在内部配合 `std::move`。


4. **移动语义**：移动构造函数和移动赋值操作符**必须标记 `noexcept**`。

---

## 六、 注释与文档规范 (Documentation & Comments)

1. **行内注释禁令**：**严禁在代码行末尾追加行内注释**（例如 `int a = 0; // 计数` 为绝对禁止），**所有注释必须独立成行**，写在目标代码的上一行。
2. **Doxygen 接口注释**：
* 仅写在 `.hpp` 头文件的函数声明处，详细标明 `@brief`（功能）、`@param`（参数）、`@return`（返回值）和 `@throws`（异常）；
* `.cpp` 的实现处**严禁重复贴 Doxygen 注释**，避免维护脱节。


3. **单行说明注释**：文件头信息、类核心职责、复杂变量说明以及非直观实现逻辑，均在代码上一行使用 `// ` 开头单独成行。
4. **任务标记**：待办事项或优化点统一单独成行，格式固定为 `// TODO: 具体描述`。
